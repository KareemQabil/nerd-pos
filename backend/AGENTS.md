# Repository Guidelines

## Project Structure & Module Organization
- `src/` contains the NestJS application (`main.ts`, `app.module.ts`) plus feature modules in `src/modules/` and shared code in `src/core/` and `src/common/`.
- `prisma/` holds the database schema, migrations, and seed script.
- `test/` contains unit/integration/e2e suites plus Jest setup/teardown.
- Build output goes to `dist/` (generated by `npm run build`).

## Build, Test, and Development Commands
- `npm run start:dev` runs the API in watch mode.
- `npm run build` compiles TypeScript to `dist/`.
- `npm run start:prod` runs the compiled server (`dist/main`).
- `npm run lint` runs ESLint (with Prettier rules).
- `npm run format` formats `src/` and `test/` with Prettier.
- `npm run test` runs Jest unit/integration tests.
- `npm run test:e2e` runs e2e tests with `test/jest-e2e.json`.
- `npm run test:up` / `npm run test:down` starts/stops the test DB (Docker).
- `npm run test:db:migrate` applies Prisma migrations to the test DB.

## Coding Style & Naming Conventions
- TypeScript + NestJS conventions: `*.module.ts`, `*.controller.ts`, `*.service.ts`, `*.repository.ts`.
- DTOs live in `dto/` as `*.dto.ts`; event handlers in `handlers/` and events in `events/`.
- Use Prettier defaults via `npm run format` and ESLint via `npm run lint`.
- Prefer repository pattern for data access and keep money math in `decimal.js`.

## Testing Guidelines
- Jest is configured to run `*.spec.ts` files from `src/` and `test/`.
- Coverage thresholds are enforced globally at 70% for branches/functions/lines/statements.
- For the test database, follow `test/README.md` (e.g., `npm run test:up`, `npm run test:db:migrate`).
- Use `TEST_CONCURRENCY=12` when running tests against shared/remote DBs.

## Commit & Pull Request Guidelines
- Recent commits use Conventional Commit-style prefixes (e.g., `fix(scope): ...`, `fix: ...`); follow that pattern for new commits.
- Keep commit subjects short, imperative, and focused on a single change.
- PRs should include a concise description, testing performed (commands), and any linked issues.

## Architecture & Constraints
- The codebase follows a modular, event-driven “LEGO” architecture (see `ARCHITECTURE-OVERVIEW.md`).
- Avoid cross-module service calls; communicate via events and handlers.
- Decimal handling is mandatory for monetary values (no native float math).
